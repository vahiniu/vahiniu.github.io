MAUDE Explorer

Live tool · FDA adverse-event data · openFDA

Type what a device is ("IVUS imaging", "insulin pump", "heart valve") and get a dashboard of what has actually been reported to FDA about it: the failure modes, the manufacturers, the harm, the recalls. Every number comes from a live query, so nothing is cached, estimated, or left over from a previous run.

I lean on MAUDE a lot at work. It's FDA's database of medical device adverse event reports, and it's the closest thing we have to a record of how a device category behaves in the field instead of how the design file says it should. The catch is getting at it: you need the right three-letter product code first, the codes are in FDA's vocabulary and not yours (there is no "IVUS" in there, only "intravascular ultrasound"), and one category's reports are usually split across several codes sharing a regulation. That lookup ate an afternoon every time, so I built something to do it for me.

What I use it for

Known use problems, for a usability or human factors file: which failures are the user and the device interacting badly, and which are already known rather than hypothetical. Risk analysis, because ISO 14971 wants post-market data feeding the hazard analysis and real counts give your severity and probability calls something to sit on, including for devices you compete with. Unmet needs, because the failure modes that show up for every manufacturer in a category, year after year, are the ones nobody has solved yet.

How it works

Describe the device in plain language and it searches FDA's classification database, expanding the acronyms FDA doesn't use. Each candidate code comes back with its regulation, class and report count, so you can see which one holds the traffic. It will pull in the rest of the regulation family too, which is the closest thing to a predicate list that's actually in the data. You approve the scope before anything runs. The dashboard ranks failure modes by volume and by harm, with each row's rank in the other ordering, since the two almost always disagree, plus a manufacturer view with harm rates and the recalls in the window.

On the limits, I was strict. MAUDE has no denominator, so none of this is a rate and the page says so. Counts are a floor. Harm rate reflects how a manufacturer classified its own reports. A failed query is flagged as an error, never counted as a zero.

One self-contained HTML file, querying openFDA straight from your browser, so nothing you type goes anywhere except FDA. Without a key openFDA allows 1,000 requests a day and a full run uses roughly 100 to 150, so about seven runs. A free key takes that to 120,000.
